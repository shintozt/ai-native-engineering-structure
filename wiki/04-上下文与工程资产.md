# 上下文与工程资产

## 适用范围

本文基于 `raw/` 中第 4 组“上下文与工程资产”材料整理，面向新需求开发场景。目标是定义新项目从第一天就应该准备的 AI 上下文资产，包括 `AGENTS.md`、代码索引、CodeWiki、参考项目、验证脚本和工程文档。

参考材料：

- `一个文件让 AI Coding 效率翻倍：AGENTS.md 实践指南.md`
- `Codeindex · 让大模型更好地理解你的代码.md`

同时参考了其他材料中关于“分层注入”“代码模式”“领域知识”“知识点召回”的相关实践。

## 核心结论

AI 写不好代码，很多时候不是模型能力不够，而是项目对 AI 不友好：项目结构、团队规矩、构建命令、验证方式、内部组件、业务术语、参考代码都不在 AI 能稳定读取的位置。

上下文工程的目标不是把所有信息塞给 AI，而是让 AI 在正确阶段、以最低上下文成本拿到最有价值的信息。

一句话原则：

> `AGENTS.md` 是地图，不是百科全书；源码是最准确的文档；索引和摘要让 AI 知道去哪找；验证脚本让 AI 改完能自证。

## 上下文资产分层

建议把 AI 上下文资产分成 5 层：

| 层级 | 资产 | 加载方式 | 作用 |
|---|---|---|---|
| L1 入口地图 | `AGENTS.md` | 静态常驻 | 告诉 AI 项目是什么、去哪找、必须遵守什么 |
| L2 项目规则 | `constitution.md`、rules、lint | 静态 + 检查 | 定义不可违反的工程约束 |
| L3 项目知识 | `context/`、CodeWiki、设计文档 | 按需检索 | 解释业务、架构、模块、历史决策 |
| L4 代码理解 | Codeindex、函数依赖图、代码摘要 | 工具检索 | 帮 AI 定位代码和理解依赖影响 |
| L5 高保真样板 | reference projects、样板代码、模板 | 按需引用 | 让 AI 模仿团队真实代码模式 |

## AGENTS.md 定位

`AGENTS.md` 是给 AI Agent 看的项目入口文件。它不是 README 的替代品，也不是完整手册。

| 文件 | 主要读者 | 重点 |
|---|---|---|
| `README.md` | 人 | 项目介绍、快速开始、贡献方式 |
| `AGENTS.md` | AI 为主，人可浏览 | 项目地图、命令、规则、验证方式 |
| `context/` | 人和 AI | 深层业务知识、架构知识、经验 |
| `harness/` | AI 和维护者 | 规则、Skill、检查脚本、模板 |

`AGENTS.md` 应控制在 200 行以内。超过这个范围，说明它正在从地图变成手册，需要把细节拆到 `docs/`、`context/` 或 `harness/`。

## AGENTS.md 应该写什么

只把两类信息直接写进 `AGENTS.md`：

1. AI 理解项目全貌的必要信息：技术栈、仓库结构、核心模块、分层架构。
2. 违反会直接导致错误的硬性规则：编码规约、命名约定、禁止项、验证命令。

判断标准：

| 信息类型 | 放哪里 |
|---|---|
| AI 不知道就会写错代码 | `AGENTS.md` |
| AI 不知道只是写得不够好 | `context/` 或专题文档，`AGENTS.md` 放链接 |
| 模块内部细节 | 对应模块文档 |
| 可自动检查的规则 | 检查脚本 + `AGENTS.md` 引用命令 |
| 组件用法、样板实现 | 参考项目或代码模式 |

## 上下文组织原则

### 1. Map, Not Manual

`AGENTS.md` 只放导航和硬规则，不放大段说明。详细内容通过链接指向深层文档。

反例：

- 把所有组件用法写进 `AGENTS.md`。
- 把完整架构设计写进 `AGENTS.md`。
- 把每个模块的业务规则都塞进 `AGENTS.md`。

正例：

- `AGENTS.md` 写“组件用法见 `context/project/components/INDEX.md`”。
- `AGENTS.md` 写“新增接口必须运行 `make test-api`”。
- `AGENTS.md` 写“禁止 Controller 直接访问 Repository，运行 `make lint-arch` 检查”。

### 2. 源码优先

内部组件、闭源 SDK、参考系统的使用文档经常滞后。对 AI 来说，源码通常是最准确的文档。

建议：

```text
reference-projects/
  internal-component-lib/
  sample-admin-page/
  gateway-plugin-example/
docs/design-docs/
  ref-internal-component-lib.md
  ref-sample-admin-page.md
```

参考文档负责告诉 AI “去哪看”，源码负责提供真实实现。

### 3. 静态规则 + 动态检索

| 类型   | 加载方式      | 例子                               |
| ---- | --------- | -------------------------------- |
| 开发规范 | 静态常驻      | 禁止跨层调用、必须使用内部组件                  |
| 代码模式 | 静态引用或按需引用 | 标准列表页、标准表单页、标准接口                 |
| 领域知识 | 动态检索      | 业务术语、组件 API、历史坑                  |
| 任务规格 | 每次需求生成    | `spec.md`、`design.md`、`tasks.md` |

关键规则必须始终在场，不能依赖 AI 主动检索；细节知识应按需召回，避免上下文膨胀。

## Codeindex 的作用

Codeindex 解决的是大型代码仓库的代码理解问题。它不是替代 `AGENTS.md`，而是为 AI 提供“找代码、懂代码、看影响面”的工具层。

核心能力：

| 能力 | 作用 |
|---|---|
| 增量索引 | 按仓库和分支建立索引，避免每次全量处理 |
| 语义检索 | 用自然语言找相关代码片段 |
| 文件摘要 | 快速理解一个文件的职责 |
| 代码片段摘要 | 快速理解局部逻辑 |
| 函数声明查询 | 找到文件内函数 |
| 函数依赖图 | 查看函数上下游调用关系 |

典型使用场景：

| 场景 | Codeindex 提供什么 |
|---|---|
| 需求分析 | 根据业务描述召回相关模块和代码 |
| 方案设计 | 理解现有实现和影响范围 |
| AI Review | 查询函数上下游，判断变更是否影响其他逻辑 |
| CodeWiki | 基于代码摘要生成仓库文档 |
| 新人 / 新 Agent 上手 | 快速建立项目结构认知 |

## CodeWiki 的作用

CodeWiki 是基于代码索引和摘要生成的项目知识文档。它适合作为 `context/project/` 的初始底座。

建议使用方式：

1. 先用 Codeindex 对仓库建立索引。
2. 生成文件级和模块级摘要。
3. 生成 CodeWiki 初稿。
4. 人工补充关键业务语义、设计原因、已知限制。
5. 将高价值内容整理进 `context/project/`。

注意：自动生成的 Wiki 是起点，不是终点。AI 能总结代码在做什么，但未必知道为什么这么做。

## 验证脚本也是上下文资产

如果 AI 不知道怎么启动、构建、测试、验证，它就只能停在“改完代码”。新项目必须把验证命令脚本化。

建议准备：

| 脚本 / 命令 | 作用 |
|---|---|
| `make setup` | 初始化依赖 |
| `make dev` | 启动本地服务 |
| `make test` | 运行测试 |
| `make lint` | 运行基础检查 |
| `make lint-arch` | 架构分层检查 |
| `make verify-api` | 接口验证 |
| `make verify-ui` | 页面验证 |

错误信息要对 AI 友好，推荐格式：

```text
WHAT: 违反了 Controller 不得直接依赖 Repository 的规则。
WHY: Controller 只能负责协议转换，业务逻辑必须进入 Service。
HOW: 将 Repository 调用移动到 Service，并由 Controller 调用 Service。
```

这样的错误输出可以直接驱动 AI 修复。

## 常见误区

| 误区 | 问题 | 建议 |
|---|---|---|
| 把 AGENTS.md 写成大全 | 上下文膨胀，关键规则被淹没 | 保持地图定位 |
| 只写规则不做检查 | AI 和人都会忘 | 重要规则脚本化 |
| 只维护文档不引入源码 | 文档滞后，边界缺失 | 内部组件尽量给源码或类型定义 |
| 只做 RAG 不做索引导航 | 召回碎片化，缺全局结构 | 索引 + 摘要 + 语义检索结合 |
| 所有知识都动态检索 | 关键规则可能没被召回 | 底线规则静态注入 |
| 所有知识都静态注入 | 上下文噪音过大 | 细节知识按需加载 |
