# 测试脚手架

## 基本原则

- 测试名表达业务行为。
- 每个边界一个测试。
- 回归 bug 必须写明曾经失败的场景。
- 不允许只有 happy path。
- 不允许没有断言。

## 层级建议

| 层级 | 测试重点 |
| --- | --- |
| domain | 业务规则和边界 |
| adapter | 转换、错误映射、fake/mock 输入 |
| infra | 连接、超时、错误处理，默认隔离真实服务 |
| app | 用例编排、异常流程、回滚降级 |
| observer | 指标、日志、debug 输出 |

## 常见错误

- 测试依赖真实外部服务。
- 测试失败时直接 skip。
- 只测试实现细节，不测试业务行为。
