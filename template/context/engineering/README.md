# Engineering 目录

本目录保存业务代码实现相关的长期工程上下文，包括模块脚手架、代码生成脚手架和可复用实现模式。

`harness/` 只负责流程控制；凡是会直接影响 `src/`、`tests/` 业务代码形态的内容，都应放在这里。

## 子目录

| 目录 | 内容 |
| --- | --- |
| `scaffolds/` | AI 可复制改造的 C++17 模块脚手架 |

## 写入原则

- 脚手架必须能被复制改造，不能只有概念说明。
- 每份脚手架必须写清适用场景、不适用场景、允许变化和验证方式。
- 从真实需求中沉淀出的代码模式，先进入 `context/learnings/`，确认可复用后再补充到 `scaffolds/`。
